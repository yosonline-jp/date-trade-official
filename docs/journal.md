# 取引ジャーナルの追加機能

## DB更新（必須）

Supabase SQL Editorで `supabase/migrations/202610020001_journal.sql` 全体を実行してください。全体をトランザクションにしており、失敗した場合は変更がロールバックされます。既存の取引と手入力収支は保持します。既存取引の公開範囲は公開のまま、新規取引は非公開を既定にしています。

追加するもの:

- trade_records: 手数料、エントリー理由、反省点、タグ、画像パス、公開範囲、取り込みキー
- daily_profit: 自動集計時の調整額
- journal_settings: カレンダー集計方法
- journal_reports: 週次・月次の振り返りと次の目標
- watchlist_notes: 非公開の分類・注目理由・想定価格
- 非公開のtrade-screenshotsストレージバケット
- 原子的な500件単位の取り込みRPCと重複用インデックス

trade_recordsとdaily_profitの既存RLSポリシーを、本人の更新・削除と公開範囲に対応したポリシーへ置き換えます。新しいメモ・レポート・設定は本人だけが読み書きできます。公開取引の画像は閲覧可能で、非公開取引の画像は本人だけがアクセスできます。画像表示は毎回アクセス権を確認するAPIを通します。

管理トークンで適用する場合は、`.env` に `SUPABASE_ACCESS_TOKEN` を設定して以下を実行できます（トークンはログに出力しません）。通常のservice_roleキーではスキーマ変更はできません。

```powershell
docker compose exec -T app node scripts/apply-journal.mjs
```

管理API: https://supabase.com/docs/reference/api/v1-run-a-query

## 利用方法

1. 取引記録: 登録・編集で手数料、エントリー理由、反省点、タグ、チャート画像、公開範囲を設定できます。公開を選ぶとメモと画像も公開対象になります。
2. 収支カレンダー: 「手入力の収支」と「実取引から自動集計」を選べます。手入力データは保持します。自動集計の各日は手数料控除後の実取引損益に調整額を加算します。デモ取引は除きます。日付から取引一覧と調整額を表示します。
3. 成績分析: 実取引／デモ、期間を指定して月・年・銘柄・売買区分・タグの組み合わせ別に集計します。最大ドローダウンは日次累積損益のピークからの最大減少額です。未決済の含み損益は含みません。
4. CSV取り込み: UTF-8/Shift-JISに対応。決済済み取引は買値・売値、約定履歴は売買・約定単価などの列を割り当てます。約定履歴は古い順に先入先出で組み合わせ、未決済や対応する建玉が不足した決済は除外して表示します。同日の順序はCSVの行順です。売買の値は買／買付／売／売却／買建／買建て／売返済／売埋／売建／売建て／買返済／買埋を認識します。他の表記はCSVで置き換えてください。証券会社固有の複数行ヘッダーなどは通常の1行ヘッダーに整えてください。
5. 売建の決済済みCSV: 既存データの慣例に合わせ、「買値」列に売建の建値、「売値」列に買返済価格を割り当てます。約定履歴は自動で変換します。
6. CSVの重複: 銘柄・決済日・建値・決済値・数量・口座種別・取引区分が同じ記録を重複として除外します。同日に全く同じ条件で複数回取引した場合も重複扱いになります。メモや手数料の違いだけでは別記録と扱いません。500件ずつ保存し、失敗したバッチは保存しません。完了済みバッチは残り、再実行時には重複を除外します。
7. 振り返りレポート: 月次または月曜始まりの週次を選び、期間内の実取引・タグ・メモを振り返り、次の目標を書いて保存します。レポートのプレビューには入力中の文章も反映します。
8. シェア: カレンダーとレポートをPNGにして保存・Xの投稿画面へ進めます。金額の非表示、元本を入力した場合の損益率表示に対応。元本は画像に含まれません。文章内の金額は自動で隠れません。XでPNGを手動添付してください。
9. ウォッチリスト: 銘柄ごとに分類・注目理由・想定価格を保存し、分類で絞り込みできます。追加メモは公開プロフィールには出ません。

## 検証

```sh
docker compose exec -T app yarn typecheck
docker compose exec -T app node scripts/test-journal.mjs
```

DBのポリシー検証は独立したローカルPostgreSQLを使います。`tests/fixtures/journal-schema.sql` はローカル検証専用の簡略スキーマです。本番Supabaseでは実行しないでください。続いてマイグレーションと `tests/fixtures/journal-rls.sql` を実行すると、本人・他人・未ログインの読み書き、画像の公開範囲、重複、取り込み失敗のロールバックを検証できます。

PC・モバイルのブラウザー検証は、一時的な検証画面を生成して実行します。実データの保存は行いません。終了後に必ず検証画面を除去してください。

```sh
docker compose exec -T app node scripts/prepare-journal-ui.mjs
docker compose -f docker-compose.yml -f compose.test.yml run --rm -e JOURNAL_UI_CHECK=1 e2e yarn playwright test tests/journal.spec.ts
docker compose exec -T app node scripts/prepare-journal-ui.mjs remove
```
