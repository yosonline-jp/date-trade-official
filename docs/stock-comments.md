# 銘柄コメントの認証と投稿

未ログインの株詳細ページでは、コメントの閲覧とログイン案内を表示します。投稿フォームはサーバーで確認済みのユーザーがいる場合に表示し、投稿時にも Supabase の getUser() で認証を再確認します。ユーザーIDはサーバーで取得したものを使います。

ログイン案内からメール・Google・Xで認証すると、元の株詳細ページのコメント欄へ戻ります。戻り先を指定しないログインは従来どおりダッシュボードへ進みます。外部URL・二重スラッシュ・バックスラッシュ・制御文字を含む戻り先を拒否し、ログイン失敗時にも安全な戻り先を保持します。

入力中にセッションが切れた場合は、入力内容を保って再ログインを案内します。ログインリンクは別タブで開くので、ログイン後に元のタブへ戻って再投稿できます。保存・通信の失敗時にも入力を残し、成功時だけ空にします。投稿中は入力と投稿ボタンを無効にします。

空白のみのコメントは受け付けず、前後の空白を除いて1～250文字をサーバーで検証します。成功後は公開用とダッシュボード用の株詳細ページを再検証し、コメント一覧を更新します。想定される認証・保存エラーは構造化した結果として返し、DBの内部情報を画面へ表示しません。

コメントのサーバー処理、ログイン復帰、未ログイン画面の26件と、既存の株詳細の操作8件をPC・スマートフォンの設定で確認しました。サーバー処理と認証成功・失敗はローカルのスタブで検証し、実DBへテストコメントを保存しません。

ブラウザーでは実際の未ログイン株詳細ページの案内と、隔離した一時ページで認証切れ・保存失敗・通信失敗・成功時のフォーム状態を各端末で確認しました。投稿中の無効化、失敗後の入力保持、成功後のみ初期化、別タブのログイン導線、横方向にはみ出さないことを確認済みです。一時ページは確認後に削除しています。
